# TRIZ Worker Bench

基线提交为 `19e20f4a2b4d2d9e0b46a214fd609146be0a7d7c`。目前为 M0 草案，开发题与通路题均为虚构。留出集只登记 4 个名额，内容与标签由独立评审者提供和保管。

1. 用三道通路题校准宿主、耗时和预算。冻结模型版本、工具权限、时间及检索额度后再跑 8 道开发题。
2. 每题、每组开新会话。A 使用共用指令，B 加普通 TRIZ 指令，C0 加基线 Skill。A/B 在无项目或用户 Skill 自动注入的环境运行，确认载入清单。C0 的 G1.5 回答在实际提出确认后才提供。各组均可提出澄清，记录实际交互。
3. 每次保存题号、提交、模型、输入 SHA256、检索式和时间、耗时、token、原始输出及重试原因。取不到的元数据写 `unavailable`。超预算也保留输出和状态。
4. 使用随机编号替换组别、模型和提交信息，两位评审各自获取随机顺序和评分表。映射表独立存放。汇总时保留原始分、分歧、关键错误和引用原句。详情见 [评分规程](rubric.md)。

## 共用任务指令

提供问题与硬约束后，请说明问题边界、作用变量与因果、候选方案机制和差异、证据来源及边界、验证设计，并给出决策摘要。缺少实测时区分假设、验证计划和已获证据。每组使用同一题面及可用资料。

## B 组附加指令

用 TRIZ 分析。识别技术或物理矛盾，解释欲改善和随之恶化的工程参数。因果不足时说明需补充的事实。应用合适的发明原理生成候选方案，解释如何作用及如何验证。

## 运行工具

参见 [M0 运行协议](protocol.md)。`bench.py` 只封装题面、采集宿主输出和校验记录，不调用模型，也不评定工程质量。

题面在 `cases/`；`cases.json` 保留不含确认的兼容目录。预设确认与评审草案在 `private/`，它是逻辑隔离目录，不是权限系统；正式运行只向被测会话提供导出的 `prompt.md` 和该组允许的资源。

C0 基线固定不变。模拟用户只用于有授权的通路校准，不能计为独立人工选择或盲评收益。M0 全部完成还需其余通路、预算冻结与独立评审准备，本次只运行 S01。

`summarize_results.py --records <运行记录...> --output <新目录>` 汇总状态与已知成本。缺失值保留 unavailable，已知部分小计不伪装成完整成本，历史输出回放不重复计入模型用量。单题发现与基线验收冲突见 [S01 发现](findings/S01-C0.md)。
