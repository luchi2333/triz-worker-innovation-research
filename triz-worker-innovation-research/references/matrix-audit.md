## 运行校验

执行：

```bash
python scripts/lookup_matrix.py --self-test
node scripts/lookup_matrix.mjs --self-test
```

两个脚本使用各自语言标准库独立校验：参数/原理数量、39×39 结构、1248 个非空单元、值域 1～40、`null` 对角线转物理矛盾、空单元报 `no_preferred_principle`、矩阵载荷哈希、#30/#31 译名、黄金单元及行列方向非对称性；同时校验 [parameter-guidance.json](parameter-guidance.json) 的 39 条词汇表与矩阵版本一致。

两个脚本的 `SELF_TEST_PASS` 输出必须逐字一致，形如：

```text
SELF_TEST_PASS parameters=39 principles=40 rows=39 columns=39 populated=1248 golden_cells=16 matrix_sha256=d8447a8f…c3ddc70
```

其中 `golden_cells` 是固定回归单元数量，两个脚本必须同为 16；任何一侧数字变化都说明回归集被改动，需要先更新本文件的分组说明。

固定回归单元共 16 个，分四组：

**历史转录差异单元（6）** —— 与在线表示存在分歧，本资源采用传统转录，是转录环节最易出错的位置：

- R1C28 → 28, 27, 35, 26
- R7C28 → 25, 26, 28
- R15C25 → 20, 10, 28, 18
- R15C31 → 21, 39, 16, 22
- R18C35 → 15, 1, 19
- R19C9 → 8, 35

**源格式清理单元（4）** —— 源 XLS 缺逗号或含重复项，已恢复并保留顺序，是清理环节最易出错的位置：

- R1C38 → 26, 35, 18, 19
- R8C25 → 35, 16, 32, 18
- R33C10 → 28, 13, 35
- R34C1 → 2, 27, 35, 11

**行列方向镜像（2）** —— 交换行列必须得到不同原理：

- R1C39 → 35, 3, 24, 37
- R39C1 → 35, 26, 24, 37

**高频场景单元（4）** —— 职工创新常见矛盾方向，同时兼作烟雾测试：

- R39C30 → 22, 35, 13, 24
- R39C31 → 35, 22, 18, 39
- R25C27 → 10, 30, 4
- R35C36 → 15, 29, 37, 28

回归单元不因某个具体课题用过而增删；新增锚点必须说明它守护的是转录、清理、方向还是边界语义。

## 行分片

`references/matrix-rows/R01.md … R39.md` 是矩阵 JSON 的确定性派生产物，供无 Python/Node 的平台只读目标行完成查询。生成与校验：

```bash
python scripts/lookup_matrix.py --emit-rows    # 由矩阵 JSON 重新生成全部 39 个行分片
python scripts/lookup_matrix.py --verify-rows  # 校验分片内容与矩阵载荷完全一致
```

行分片禁止手改；矩阵更新后必须重新生成。`validate_skill.py` 在每次校验时运行行分片一致性检查，分片与矩阵载荷任何不一致都判失败。

## 使用边界

经典矩阵是历史经验检索工具，不是统计因果模型。参数映射存在工程判断，翻译也可能有不同版本。资源的完整性校验只能证明“查到了内置表中的确定单元”，不能证明参数选择正确、原理适用、方案新颖、可制造、安全或有效。
