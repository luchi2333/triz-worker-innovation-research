# 工程一致性复核任务卡

本文件把“研究逻辑看起来完整”转换为可逐项复核的工程关系。仅在对应条件触发时读取；简单流程题不填电气卡，非测量方案不填可辨识性卡。

## 1. 变量方向与真实矛盾卡（G1）

现在核查：矛盾是否由同一个可调控制量的改变真实引起。

从哪里取证：`research-record.json` 的 `variables` 与 `contradictions`，以及现场事实/来源卡。

固定输出：

```text
控制变量 X → 改变方向 → 有用结果 → 同次改变引发的恶化 → 因果依据 → EC2 反向情况
```

合格要求：

1. X 是可调输入，不是“提高质量、提高可靠性”之类愿望；
2. 目标量和风险量有单位或明确为无量纲，并写清越大、越小或区间内更好；
3. 用两个简化输入检查方向；阈值比较式必须写出 `below/above`；
4. 恶化确由 X 的改变造成，而非原本就存在的噪声、约束或安全要求；
5. EC2 写出反向改变下的两种结果，不只写“反向”；
6. 关系不成立时设为 `assumption_only`、`reframe_required` 或 `no_triz_contradiction`，不得强行查矩阵。

错误例：某量低于阈值报警，却声称降低阈值会更早报警。

合格例：风险在测量量低于阈值时触发；提高阈值会更早触发，但正常波动引起的误报警也增加；两种结果均有比较式或代理证据。

失败后：退回因果链，验证变量方向或重构问题；保留 G1.5 用户确认门。

## 2. 端到端能力与模块衔接卡（G3）

现在核查：各模块组合后，是否在同一对象、范围和环境内完成用户真正需要的结果。

从哪里取证：`routes[].steps/components/active_effects/interactions/interfaces/capability_range`。

逐步回答：

- 用户要的是发现异常、定位支路、定位故障点，还是直接消除故障？
- 每一步的输出能否作为下一步的输入？`compatible`、`conditional` 或 `gap` 必须明确。
- 所有连续必需步骤的共同覆盖范围是什么？条件分支应分别计算，不能把备选路径错误取交集。
- 哪些模块主动施加力、电、热、磁、化学或控制动作？哪些只是读取信息？
- 两个主动模块是否互扰；断电、断线、失控或模块失效时如何退出？
- 集成或裁剪后是否丢失安全、质量检查、维护或接地功能？

错误例：上游覆盖 1—10，下游必需步骤只覆盖 1—3，却宣称系统覆盖 1—10。

合格例：系统能力明确收缩至 1—3；3—10 列为缺口，并给补试验或替代分支。

失败后：缩小路线允许范围、增加适配模块，或将路线退回候选，不得用成熟部件的等级替代完整系统等级。

## 3. 测量与识别最小可辨识性卡

当 `mechanism_kind` 为 `electrical_measurement`、`measurement` 或 `diagnosis` 时必须填写：

| 项 | 最少回答 |
|---|---|
| 激励/自然输入 | 系统怎样被激发；是否主动注入 |
| 观测量 | 实际测到什么、在哪个端口、参考点是什么 |
| 未知量 | 试图识别哪个参数、状态或位置 |
| 参考量 | 用什么基准区分漂移、环境变化和真实故障 |
| 关系式/因果模型 | 为什么这些观测足以支持输出 |
| 主要干扰 | 环境、耦合、传感器、数据缺失和操作影响 |
| 输出不确定性 | 多解、范围、置信或“不可判定”出口 |

多个解能解释同一观测时，输出候选集合或不可判定，不得只给一个精确答案。无主动注入只能排除一种干扰来源，不能自动证明接入安全、算法可靠或不误报。

## 4. 工程图语义卡（G5）

每张核心图上色前先写：

1. 对象是什么；
2. 每根主线/箭头从哪里到哪里，表示物理连接、能量、信号、数据、运动还是假设关系；
3. 输入怎样导致输出；
4. 哪些内容尚未证明。

电气/测量图至少标出端口、参考地/参考点、传感器、能量回路和信号方向；控制图至少有输入、状态、判断、输出、异常分支；热/流体图至少有源、介质、边界、入口出口与泄漏/过热路径。线条若未连接到合法端口，必须修图或标“省略/未知”，不能让悬空线看似完整回路。

工程视角复核要留下实际发现：关键箭头清单、最危险误读、修正或保留理由。首次阅读者复核要留下只看图得到的 2—3 句复述和仍不理解的点。只写“PASS、读者能理解”不算复核证据。

## 5. 三种状态必须分开

- 结构校验：文件、编号、链接、图像、散列和字段是否齐全；
- 可计算一致性：计数、引用、评分覆盖、公式、单位和图序是否一致；
- 工程内容复核：物理关系、模块衔接、图线含义和安全边界是否由适当人员复核。

前两项通过不能自动把第三项写成“已验证”。`complete` 只表示约定格式交付完成；V0—V3 和允许动作仍由证据决定。
