# 工程图规划与技术可视化

本文件是 G5 工程图规划的唯一权威规则。目标不是增加装饰图片，而是让没有参与前期研究的工程人员只看核心图组和图题，也能复述“对象是什么、方案怎么动、为何起作用、保护谁、哪里危险、哪些尚未验证”。

## 1. 先规划图，再生成图

每个最终推荐方案先回答四个问题：

1. 读者最需要通过图片理解什么：结构、相对位置、动作顺序、作用路径、安全边界还是方案差异？
2. 如果没有图片，哪一段最容易被误解？
3. 核心创新属于结构、运动、作用机理、工艺流程、控制逻辑、系统架构还是超系统改变？
4. 是否涉及实体结构、相对运动、力/能量、材料变形、流体、热、电、磁、光、多阶段动作或安全边界？

把答案写入 `deliverables-manifest.json` 的 `concept_profile` 与 `figures`。每张图必须有一个 `decision_question` 和一个 `main_message`：前者说明图要回答什么，后者说明读者看完应得到的唯一结论。无法写出这两个字段的图通常不应进入主报告。

固定顺序：

```text
技术方案
→ 识别读者必须理解的问题
→ 冻结 Figure Plan
→ 选择图型
→ 标记事实/来源/假设/未知
→ 生成 SVG 单一来源和 PNG 渲染
→ 工程师视角 + 首次阅读者视角复核
→ 图文一致性与机器校验
→ 嵌入报告
```

## 2. 九类工程图

`figure_type` 使用以下固定值；`type` 仍表示交付角色，两者不得混用。

| 编号与值 | 主要回答 | 最低内容 |
|---|---|---|
| `F1-object-structure` | 对象/设备由什么组成？ | 层级、部件、相对位置；确认、代理、候选、未知状态 |
| `F2-problem-failure` | 当前动作为什么失败？ | 当前动作→物理作用→失效→工程后果 |
| `F3-system-architecture` | 模块如何连接？ | 模块、接口、输入输出；不能代替机械原理图 |
| `F4-mechanism-section` | 谁通过什么界面作用于谁？ | 工具、对象、接触界面、作用、结果 |
| `F5-motion-sequence` | 方案按什么顺序运动？ | 3～6 帧状态、主运动箭头、每帧输入与结果 |
| `F6-force-energy-material-path` | 力、能量或材料如何传递？ | 起点、路径、方向、转换、终点和损失/副作用 |
| `F7-safety-boundary` | 怎样保护对象并限制危险？ | 工作区、被保护区、禁止越界面、独立屏障、失效后果 |
| `F8-process-operation` | 操作者怎样完成完整作业？ | 准备、定位、核心动作、检查、清理、异常回退 |
| `F9-validation-decision` | 如何验证和做决定？ | 样本、指标、通过/停止/升级、成熟度或情景区间 |

流程/因果/状态图可以使用 Mermaid 或平台原生图形；空间结构、机械机理和安全边界优先使用自绘 SVG 或原生可编辑剖面图。架构图不能代替原理图。写实渲染或 3D 概念外观只能作为 `Concept Visualization`，不能替代 F4、F5 或 F7。

## 3. 核心方案最低绘图契约

当 `concept_profile.primary_engineering_concept=true` 且方案涉及实体、运动、作用传递或材料变形时，核心方案不得只有 F3 架构图，至少包含：

```text
F4 核心结构/机理剖面
+ F5 运动序列
```

若 `safety_risk=true`，再加 F7；若 `multi_step_operation=true`，再加 F8。核心推荐路线通常应有三张图：结构/机理、工作过程、安全边界；复杂动态机理再增加 F6 作用路径。每个入选路线仍至少有一张 `solution-mechanism` 角色图。

一张图只回答一个核心工程问题。不要让一张图同时承担结构、双模式、运动、保留功能、安全边界和现场流程。应拆成“长什么样”“怎么动”“为什么有效”“怎样防止伤害”等独立图。

## 4. Figure Plan 字段

每张必需图在 manifest 中至少填写：

```json
{
  "id": "FIG-6-1",
  "number": "6-1",
  "chapter": 6,
  "type": "solution-mechanism",
  "figure_type": "F4-mechanism-section",
  "title": "受控工具界面与目标层分离机理",
  "decision_question": "工具通过哪个界面改变目标层而不进入被保护区域？",
  "main_message": "受控界面只对目标层施加作用，独立机械边界限制进入深度。",
  "subject": "通用分层工件处理机构",
  "confirmed_elements": [],
  "hypothetical_elements": [],
  "unknown_elements": [],
  "motions": [],
  "forces": [],
  "energy_flows": [],
  "protected_objects": [],
  "hazards": [],
  "safety_barriers": [],
  "labels_required": [],
  "evidence_ids": [],
  "claim_limit": "V0 概念机理，尺寸与安全能力待验证",
  "design_status": "V0",
  "source_svg": "figures/FIG-6-1.svg",
  "render_png": "figures/FIG-6-1.png",
  "path": "figures/FIG-6-1.png",
  "alt": "……",
  "routes": ["R1"],
  "required": true,
  "ledgered": true,
  "embedded_in": ["decision-summary", "main-report"]
}
```

`design_status` 直接使用全 Skill 唯一的 V0—V3，不得另建“图示成熟度”。图中出现尺寸、能力或性能数字时，必须列入 `evidence_ids`，并在标签中用“实测/现场报告/来源标称/情景目标”等词说明证据等级。

## 5. 视觉语义

默认语义不绑定唯一 RGB，必须兼顾打印和色觉差异：

| 语义 | 颜色建议 | 非彩色冗余编码 |
|---|---|---|
| 有用作用、正常运动、主要结构 | 深蓝/青蓝 | 实线、粗主箭头 |
| 危险、停止、禁止越界 | 红 | 禁止线、警示符号、文字标签 |
| 工具/机构实体 | 深灰 | 实线轮廓 |
| 被加工/去除材料 | 橙/铜色 | 纹理或材料标签 |
| 被保护对象 | 浅橙 | 独立填充和“被保护”标签 |
| 工程假设、候选或隐藏结构 | 浅灰 | 虚线轮廓或虚线箭头 |

线型固定含义：实线轮廓=当前已确认/明确设计对象；虚线轮廓=假设、候选或隐藏结构；粗箭头=主工作运动；细箭头=次级运动；双箭头=可调范围；虚线箭头=假设作用路径。复杂图必须提供简短图例。

未验证的安全屏障必须明确标为“候选屏障，需 V1 验证”或等价文字，不能画成已经成立的保险结构。对象身份未冻结时，候选结构标 `H/candidate`；可靠来源但目标适配未确认时标来源 ID，并写“待适配”。

## 6. 动态机理必须画成序列

凡核心机理依赖插入、旋转、推、拉、翻转、膨胀、收缩、解绕、切削、展开或折叠，优先使用 3～6 帧 F5，而不是单帧加许多箭头。每帧只表达一次主要状态改变：

```text
初始状态 → 接触/进入 → 作用/变形 → 释放/输出
```

若包含几何或材料机理，至少一个局部放大框应直接画出真正改变的结构，而不是只用斜线纹理代替；公式仅放小型证据框，主视觉先用“输入变化→中间机理→目标结果”说明。

## 7. 可读性与文件要求

- A4 正文阅读倍率下文字仍可辨认；SVG 字号低于 6 px/pt 判失败，低于 8 警告。
- 一张图若需要超过约 8～10 个长标签，优先拆图。
- 技术图使用 SVG 作为单一来源，并提供 PNG 渲染用于 DOCX 与预览；两者必须来自同一版本。
- SVG 必须有 `width`、`height`、`viewBox`、`title`、`desc`；F4/F5/F7 不得只有矩形、文字和装饰箭头。
- 必需标签写入 `labels_required`，校验器会在 SVG 文本中逐项查找。
- 图号采用“章号-顺序”，按报告出现顺序递增；图题说明读者要看什么，不写只有“原理图”的空标题。
- 图后用 `main_message` 生成一句“图示要点”；`claim_limit` 只保留一行必要边界，完整审计字段放台账。

## 8. Figure Review 门

G5 完成前必须做两种视角检查，并在 manifest 的 `figure_review` 记录证据：

**工程师视角**：能否区分作用件、被作用件、被保护件、运动方向、输入输出、作用路径、安全边界和待验证量？

**首次阅读者视角**：遮住正文，只看核心图组和图题，能否在 3～10 秒说出“大概怎么工作”，并在 30 秒内复述主要动作链和一个关键未验证项？

还须逐项检查：

1. 图与正文是否使用同一对象、动作、路线号和成熟度；
2. 图中有没有正文未提出的部件、尺寸、材料或性能；
3. 正文核心动作是否在图中可见；
4. 安全屏障是否独立，假设是否显式；
5. 图题和替代文本脱离正文是否仍可理解；
6. 黑白或低饱和打印后是否仍能区分语义。

任一核心问题回答“不通过”时，回到 Figure Plan 拆图或重画；不得用模型自评高分代替文件、标签、图号和字体的确定性校验。

若平台经能力探测确认无法生成或渲染图示，交付状态必须降为 `degraded`；四项图示复核记录为 `not-applicable` 并写明能力证据，不能伪造已完成的视觉检查。

## 9. 报告中的图示分层

- `Tier A` 核心决策图：4～7 张，放主报告和必要的决策摘要，覆盖问题、推荐机理、推荐系统、安全和验证。
- `Tier B` 支持性工程图：TRIZ 追溯、备选路线、FMEA、结构对比，可放正文或附件。
- `Tier C` 审计图与生成记录：图示台账、来源关系、文件路径和 QA 记录，放附件。

决策摘要第一页应出现推荐方案总图或核心动作图；核心原理章节原则上至少一半版面用于“图 + 100～250 字说明”，不再用 600～1000 字纯文字承担动态机械机理。效益为 H 情景时，优先用区间带、范围条、斜线或虚线表达，不用看似实测的实心单值柱状图。

## 10. 禁止事项

- 不用艺术风格掩盖技术关系；不用写实产品图暗示已经定型。
- 不用漂亮 3D 外观替代剖面、运动和安全图。
- 不编造尺寸、公差、材料、限力值、切深、效率或安全能力。
- 不把来源产品照片改色后当作本项目方案。
- 不让图示表现出的成熟度高于证据成熟度。
- 不因无法生成高级图片就用架构框图冒充机理图；应降级为带编号的剖面/序列 SVG 或清晰文字结构示意。

完成标准不是“报告有图”，而是核心图组减少了读者理解工程机理所需的文字，并且图中每一个关键声称都能回到事实、来源、假设或验证。
