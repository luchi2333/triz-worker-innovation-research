# TRIZ 职工创新研究流程 v2.2

阶段编号以 `G0 → G1 → G1.5 → G2 → G3 → G4 → G5` 七状态为唯一体系，与 `SKILL.md`、`weak-model-playbook.md` 一致。正文小节 0—13 只是内容组织顺序，映射见文末「阶段闸门总览」。

## 总原则

研究采用闭环而非单向流水线：

`现场问题 → 证据化问题卡 → 系统/根因 → 矛盾与矩阵 → IFR/资源/物—场 → TRIZ 完整方向稿 → 用户确认 → 多轨深研 → 来源核验与综合 → 模型回灌 → 候选方案 → 硬门槛 → 决定性验证 → 安全/IP/效益 → 技术方案报告 → 逐页/逐命题复核 → 流程复盘`

查新、试验或反证发现模型错误时，回到相应上游步骤并保留版本记录。不得为了维持原方案而选择性忽略冲突证据。

任何现场人员否决某个方案、假设或数据时，把否决原文记为 `F`/约束并做影响分析（见 [weak-model-playbook.md](weak-model-playbook.md) 1.3）；否决不触发全局暂停，只回灌受影响的结论和路线。

## 0. 立项锚定

信息采集按 [intake-guide.md](intake-guide.md) 执行：先抽取已有信息，最多补问 1—3 个会改变对象、安全或目标的关键问题，不固定逼问清单。记录：

- 用户原述、问题发现者和日期；
- 对象、工序、现场场景、上/下游边界；
- 代表型号、单位、术语和后续修正；
- 期望成果形态和明确不做事项；
- 需要授权的外部动作与禁止扩张范围。

输出：`00-研究台账.md`。之后每轮更新当前阶段、已确认事实、假设、缺口、决策与流程改进。

## 1. 证据化问题卡

把抱怨转成可验证问题：

- 谁在什么条件下执行什么完整工序；
- 时间、人力、质量、风险、等待、返工和清理分别是多少；
- 哪一步是真正瓶颈，哪一步只是最显眼；
- 必须保留的功能、禁止损伤的对象、法规/工艺硬约束；
- 现用方法和成熟替代方法，而不只记录最差基线。

标注 `F/M/S/H`。数值必须带口径，例如“约 t min/件”不能改写成“t min/m”。项目相关数字不得外推为普遍基线。

先执行 [engineering-claim-safety-checks.md](engineering-claim-safety-checks.md) 的标识身份门：逐字冻结型号、物料号、标准号和版本；疑似规范名/错字只建并列假设。身份差异若可能改变结构、尺寸、接口、保护功能或安全方法，未取得目标铭牌、证书、项目文件、原厂对应数据或实物前，不得冻结结构或给出适配结论。

问题陈述建议：

`在[场景]中，[对象/工序]因[经证据支持的机理或待验证假设]造成[可测后果]；需要在不牺牲[硬约束]的情况下改善[指标]。`

## 2. 选择证据模式

### A. 直接证据模式

有照片、剖面、样件、工艺卡或计时数据时：核对对象身份，建立分工序实测基线，优先进行低风险观察与测量。

### B. 代理证据模式

用户要求跳过照片/样件，或暂时无法取得时：

1. 建立至少三类合理结构/工况情景，包含项目自定义命名可能；
2. 采用尺寸区间、可调接口和最不利条件，不冻结危险参数；
3. 为每项判断标证据置信度，列出支持、反对、剩余未知和推翻条件；
4. 用标准、专利、厂家资料、论文机理、FMEA 和敏感性分析继续研究；
5. 把照片/样件保留为技术冻结前的验证输入，而不是当前阻塞项。

代理证据模式不得输出实测效果、适配承诺、定型图或现场可用结论。

## 3. 系统、功能与根因建模

至少完成：

- 超系统—系统—子系统边界；
- 组件—功能模型，标出不足、有害、过度和缺失作用；
- 完整工序和时间链；
- 因果链或因果轴，区分症状、直接原因和根因假设；
- 九屏幕（系统层级 × 过去/现在/未来）；
- 可用资源：物质、场、空间、时间、信息、结构、废物和超系统资源。

根因假设必须连接到可观察现象和未来反证，不能只写抽象词如“效率低”“结构复杂”。

## 4. TRIZ 矛盾建模与矩阵

形成技术矛盾、物理矛盾和管理/约束冲突，但不要混用工具：

- 技术矛盾：按 [matrix-usage.md](matrix-usage.md) 写 EC1/EC2，映射 39 参数，运行确定性脚本并返回查表结果。
- 物理矛盾：同一参数需要相反状态，使用空间、时间、条件或系统层级分离。
- 非技术约束：法规、预算、许可和组织流程不能伪装成矩阵参数；单独处理。

至少检查主矛盾和 1～3 个次矛盾。过多参数对会稀释重点；每个单元都必须有现场量和映射理由。

## 5. IFR、资源、物—场与演化

用多模型交叉校验矩阵，而不是只列原理：

- 理想最终结果（IFR）：有用功能自发实现，有害作用趋近零，新增资源最少；
- 资源分析：优先利用现有几何、废料、反力、时间窗口、信息和超系统设施；
- 物—场分析：明确两个物质和作用场；不足作用需增强/引入场，有害作用需隔离、转化或引入第三物质；
- 演化趋势：动态化、可控性、分割/集成、从宏观到微观、向超系统迁移等只作为方向，不作为历史必然规律。

输出“原理/模型 → 作用机制 → 所用资源 → 预期改善 → 新风险 → 反证”的突破口表。

## 5.5 TRIZ 完整方向稿与用户确认

按 [triz-analysis-output.md](triz-analysis-output.md) 形成用户可读的完整分析，不只返回参数编号或零散方案。必须把每个候选机制标为 F/M/S/H，并纠正参数名称、矩阵单元、物理矛盾和标准解编号。

方向稿最后按 [triz-analysis-output.md](triz-analysis-output.md) 第 12 节输出**白话确认卡**（现场话复述 + 矛盾白话 + 编号方向 + 回复选项）。此处是强制暂停闸门：

- 用户明确选定方向后，记录确认日期、确认范围和被选方向，进入阶段 6；
- 用户补充/纠正后，回到阶段 1～5 更新并重新提交；
- 用户只认可部分方向时，仅对被认可部分深研；
- 用户回复“你看着办”时，追问一句推荐确认（“建议按 ①②③ 深研，是否继续？”），仍需明确肯定答复；
- 用户只要方向稿时按交付层级 `direction` 收尾；
- 用户未回复或表达不确定时，不开展系统性产品、专利、论文和方案深化。

为避免输出明显错误而进行的少量参数查表、标准术语或来源核验不算越过闸门，但不得借此形成定型结构或效果承诺。

## 6. 可复现联网查新

前置条件：用户已明确确认阶段 5.5 的研究方向。确认范围外的新方向必须重新征求意见。

本阶段完整执行 [deep-research-protocol.md](deep-research-protocol.md)。不依赖外部 deep-research Skill；一个模型按检索者、核验者、综合者、反对者和编辑者五个视角串行执行即可。

### 检索轨道

1. 标准、监管和现场工艺：确定禁止事项、接地/安全/验收硬约束；
2. 精确型号与结构：优先制造商数据表、项目采购/设计文件；型号字符串不能代替实物层序；
3. 现成产品：厂家官网、原始手册、行程/尺寸/周期/部署边界；
4. 专利：同对象、同功能、同机理、相邻动作链；核对权利要求、同族、优先权和法律状态；
5. 论文与工程机理：材料行为、摩擦、切削、损伤、检测和人因；
6. 跨行业类比：按功能和失效搜索，不只按产品名称；
7. 反对证据：主动搜索失败、事故、限制、替代采购和使自研无必要的证据。

### 检索记录

每一轨逐条记录日期、数据库/域名、未经改写的原始检索式、语言/地域/年份/分类过滤、可见命中范围、纳入/排除及理由、来源链接、支持的具体命题、证据维度和局限。关键事实尽量由独立来源交叉核对；标准/监管官方题录本身可以作为版本状态的一手依据。没有逐条日志不得统计检索组数、声称饱和或通过查新闸门。

### 来源优先级

`官方标准/监管/专利原文/论文原文/厂家原始资料 > 学术或行业二次来源 > 经销商/聚合页 > 未核实讨论`

来源等级高不等于技术适配度高。把来源存在性、权威性、命题直接性、独立性、时效性和目标适配分开记录。厂家周期数据通常是厂内特定条件，不得直接外推到现场完整流程；产品标称尺寸范围也不得替代目标尺寸测量和样件适配。

### 负面与知识产权结论

- 写明“截止日期 + 检索范围 + 组合约束 + 未发现”，不用绝对存在性结论。
- 查新只支持技术空间判断，不等于专利新颖性、创造性或 FTO 法律意见。
- 专利摘要用于发现，关键碰撞必须回到独立权利要求和法律状态。
- 不得从“未发现完全覆盖”推出 FTO 通过、侵权豁免、可专利性或国内应用空间；仅给潜在重叠和专业复核事项。

## 7. 证据综合与模型回灌

建立证据矩阵：一行一个可核查命题，不是一行一个网页。分别写支持、反对、适用边界和对模型的影响。

输出：

- 已成熟子功能；
- 尚未发现满足的组合约束；
- 高拥挤机理族与应避开的特征；
- 可以借鉴但不能直接照搬的跨行业机制；
- 因查新而修正的根因、矛盾、IFR 或需求。

进行 Devil's Advocate 检查：最强反对意见是什么？什么证据会使项目转向采购、流程优化或停止自研？

对产品适配、跨行业/跨对象类比和“未检得”分别填写 [engineering-claim-safety-checks.md](engineering-claim-safety-checks.md) 的适配表、类比迁移卡和 N0～N3 覆盖表。关键边界不同只能支持候选机理，不能支持目标可行性。

## 8. 候选方案综合

先形成不同作用拓扑，再比较结构细节。每个候选写：

- 解决的需求、根因和矛盾；
- 使用的矩阵原理及其他 TRIZ 模型；
- 完整动作链、力/能量/信息链和系统边界；
- 与现成产品/专利的相同与差异；
- 关键未知、最敏感参数和安全失效；
- 最低成本决定性试验。

至少保留：成熟工具基准、一个低风险工程后备、一个高潜力探索路线，以及采购/预制/工序前移等超系统路线（若适用）。

## 9. 两级评价

### 一级：硬门槛

典型门槛包括：

- 不得伤害人、目标对象和需保留功能；
- 失效趋向安全、危险能量受限、可停止/回退；
- 碎屑、污染、卷入和误操作可从源头控制；
- 关键法规、工艺和现场准入无必然冲突；
- 高相关有效权利要求没有把核心动作链完全封死。

对每个声称的止挡、保护、联锁和失效安全机制填写“安全屏障真实性表”。被加工对象自身材料、摩擦/自锁、操作者手感、软件判断或单一传感器未经最不利验证不得当作安全屏障；存在此类依赖时硬门槛直接失败。

任何硬门槛失败不得用高效率评分补偿。

### 二级：加权评分

按具体项目定义权重，例如质量/安全、效率、通用性、便携、成本、制造、维护、IP 空间。公开指标定义、权重、0/1/3/5 锚点、评分者和证据 ID；未知项写 `?`，不按乐观值补分。分开报告：

- 可行性/价值分：如果关键假设成立，路线值得程度；
- 证据置信度：支持该假设的证据强度。

高分低置信度路线只能作为最先否证的探索，不得直接定案。

## 10. 最小决定性验证

验证顺序：

1. 材料/几何代理，仅观察机理和失效；
2. 退役或同批短样，允许破坏性解剖；
3. 长段/长周期连续性；
4. 完整流程，与成熟基准比较准备、动作、检查、清理和返工；
5. 模拟现场；
6. 获得技术、安全和项目审批后的现场试用。

每级规定对象身份、变量、对照、样本独立性、样本量依据、最不利包络、记录字段、检测方法/检出限、合格标准、立即停止条件、全部完成条件和升级条件。升级条件不得少于本级全部样本与判据；目视不能自动证明无隐蔽损伤，按风险增加剖切/显微或批准的等效检测。最快一次不能代表效率；报告中位数、P90、完整分布和全部失败。质量/安全硬门槛先通过，才计算效率收益。

## 11. 安全与 FMEA

定义预期用途、禁止用途和可预见误用。按“本质安全设计 → 工程防护 → 安全控制 → 信息/管理”排序；培训和标签不能替代可通过结构消除的危险。

危险表至少包括：危险事件、后果、原因、现有/建议控制、残余风险、验证编号和停机条件。控制系统目标等级只有在正式风险评估后确定，不凭空指定。

## 12. 知识产权、效益与实施

- 列出潜在差异特征，不把需求列表直接写成创新点；正式申请前复核权利要求、同族和法律状态。
- 效益包含完整人工时、一次合格率、返工、准备/清理、临界批量和全寿命成本；无实测时只给公式和数据表。
- 区分人工时节省与关键路径工期节省；不在关键路径上就不宣称项目提前。
- 制定概念、机理、Alpha、完整流程、模拟现场、推广等分阶段闸门及退出自研条件。

## 13. 最终报告、阶段结论与流程复盘

按 [final-report-blueprint.md](final-report-blueprint.md) 形成“决策摘要 + 最终研究报告 + 技术证据附件 + 来源/图示台账”。决策摘要以技术方案为主，必须直接说明平台组成、各路线采用的方法及解决的难点、推荐方案动作链、效益、安全和最小验证；AI 辅助说明、宣传禁语和内部治理内容放入附件，不单独占用摘要章节。

普通水平模型或上下文紧张时，按 [weak-model-playbook.md](weak-model-playbook.md) 逐阶段填表、检查和修复。

阶段结论采用“允许/不允许”口径：

- 当前证据支持到哪一级；
- 推荐架构、工程后备和现实基准；
- 最强支持与最强反对证据；
- 当前允许继续的动作；
- 当前禁止的声称和动作；
- 下一项最低成本决定性试验；
- 触发暂停、退出或转向采购的条件。

上游失败必须向下游传播：身份未冻结则只给代理概念；检索日志不完整则深研不通过；安全屏障未经验证则路线不通过硬门槛；验证不一致则不得升级成熟度。最终报告首页和结论显示最高证据等级，不能因文档完整而升级为制造、试用或现场放行建议。

最后记录流程版本变更：触发证据、旧规则造成的问题、新规则、预期效果及后续案例验证要求。

## 阶段闸门总览

**本文件的 G 编号是唯一编号体系**，与 `SKILL.md` 和 `weak-model-playbook.md` 完全一致：`G0 → G1 → G1.5 → G2 → G3 → G4 → G5`。任何文件不得再定义第二套 G 编号。

| 状态 | 名称 | 通过条件 | 失败去向 |
|---|---|---|---|
| G0 | 立项与问题锚定 | 原始标识逐字冻结；F/M/S/H 分开；术语、口径、边界、硬约束和证据模式明确 | 回到用户原述与目标铭牌/项目文件；不静默纠错；缺数据则建情景包络，不伪精确 |
| G1 | 系统与 TRIZ 建模 | 完整工序、根因、EC1/EC2、参数映射、确定性查表（Python/Node/行分片三选一）、IFR/资源/物—场齐备 | 重写矛盾或补齐工序；不凭记忆补原理 |
| G1.5 | 用户方向确认 | 完整方向稿已提交；用户**明确**确认边界、优先矛盾和进入深研的候选 | 补充/修正后重新提交；未收到明确确认不得进入深研 |
| G2 | 深度研究 | 逐条日志可复跑；来源五维核验；标准、产品、专利、机理、跨行业和反对证据覆盖；查新结果已回灌模型 | 扩检或转采购/流程方案；日志不全不得通过 |
| G3 | 候选方案与选择 | 含成熟基准、低风险后备、高潜力探索、超系统替代；独立安全屏障硬门槛通过；评分可复算且与证据置信度分离 | 淘汰或重构作用拓扑 |
| G4 | 验证、安全与效益 | 分级决定性试验、FMEA、安全屏障真实性、效益公式与情景齐备；验证成熟度达到本任务要求（见 V0—V3） | 停止路线、返工设计或退出自研；不靠增大能量挽救 |
| G5 | 报告与独立复核 | 摘要技术导向；主报告/证据附件/台账一致；来源、数字、图片和版式实际检查通过 | 修订后重新渲染和抽查，不以文件存在代替验收 |

### 验证成熟度 V0—V3（G4 内部，不是独立阶段）

验证成熟度描述"证据到了哪一步"，不改变七状态顺序，也不因提高成熟度而自动获得制造、试用或现场放行资格。

| 成熟度 | 含义 | 通过条件 |
|---|---|---|
| V0 概念证据 | 机理可行，无原理性阻断 | 关键机理有来源或最小试验证据；未发现不可绕过的物理或法规阻断 |
| V1 短样 | 代表性短样通过 | 至少一条路线真实短样在预设检测范围内无不可接受损伤且风险可控 |
| V2 完整流程 | 完整节拍与质量通过 | 长段/完整节拍、质量、安全和基准比较通过 |
| V3 受控现场 | 现场条件满足 | 正式风险、审批、工艺、IP 和真实效益满足 |

标准研究默认交付到 V0/V1；只有在用户明确要求试制、申报或推广，且具备相应证据时，才把 G4 的验证成熟度提高到 V2/V3。
