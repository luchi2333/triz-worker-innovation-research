# 39×39 矛盾矩阵使用规范

## 1. 适用边界

经典阿奇舒勒矩阵用于两个不同工程参数之间的技术矛盾。它不是需求分类表、答案库、物理矛盾对角表，也不能替代根因分析、专利查新和验证。

矩阵固定方向为：**欲改善参数作为行，随之恶化参数作为列**。查询记作 `R改善 × C恶化`，交换行列往往得到不同原理。

## 2. 先写 EC1 / EC2

用同一个控制变量 `X` 写两种相反状态：

- `EC1：IF 增加/采用 X，THEN 改善 A，BUT 恶化 B。`
- `EC2：IF 减少/取消 X，THEN 改善 B，BUT 恶化 A。`

若 EC2 不能自然反转，通常说明把无关副作用、多个控制变量或解决方案偏见混入了矛盾。先修正矛盾，不急于查表。

## 3. 从现场量映射参数

1. 先写现场语言、单位、测量方法和目标方向，再选择标准参数。
2. 选择能表达决策目标的参数，不选择方案动作本身。例如“单位时间合格产出”优先映射 #39 生产率；只有局部运动速率才优先映射 #9 速度。
3. 列出 2～3 个可能参数，说明纳入/排除理由。主参数应让矛盾最可测、最少歧义。
4. #30 是外部作用施加给目标对象的伤害；#31 是对象或过程自身产生并危害环境、人员或其他对象的因素。
5. “改善时间”通常写成减少 #25 时间损失；在表述中明确方向，避免把“参数编号”误当“越大越好”。

完整 39 参数可运行：

```bash
python scripts/lookup_matrix.py --list-parameters
node scripts/lookup_matrix.mjs --list-parameters
```

不确定现场说法对应哪个参数时，先查候选（结果只是映射候选，不能自动替代工程判断）：

```bash
python scripts/lookup_matrix.py --search "看不清"
node scripts/lookup_matrix.mjs --search "费劲"
```

查参数定义、现场说法、可测量方式和易混参数判据：

```bash
python scripts/lookup_matrix.py --explain 30
node scripts/lookup_matrix.mjs --explain 30
```

`--search` 与 `--explain` 的数据来自 [parameter-guidance.json](parameter-guidance.json)（39 参数现场词汇表），与受审计的矩阵 JSON 相互独立。易混对重点核对：#30/#31（外界伤害对象 vs 对象伤害外界）、#28/#29（测得准 vs 做得准）、#9/#39（局部速度 vs 整体产出）、#25/#15（时间浪费 vs 动作时长）。

## 4. 强制查询

对每个最终采用的参数对运行（本节是查询命令的权威定义）：

```bash
python scripts/lookup_matrix.py --improve 1 --worsen 28 --format markdown
node scripts/lookup_matrix.mjs --improve 1 --worsen 28 --format markdown
```

多个参数对用一次批量查询，避免多次调用并便于同屏比较：

```bash
python scripts/lookup_matrix.py --batch "1x28,39x30,25x27"
node scripts/lookup_matrix.mjs --batch "1x28,39x30,25x27"
```

版本核对（skill 版本、矩阵版本、词汇表版本）：

```bash
python scripts/lookup_matrix.py --version
node scripts/lookup_matrix.mjs --version
```

不要手抄或凭记忆填单元。两个脚本都只使用标准库，读取 `contradiction-matrix.json`、校验 39×39 结构和哈希，并返回参数名称、方向与原理原顺序。Python 与 Node 对同一子命令的输出逐字一致；错误信息统一为“问题 | 给定 | 修复建议”格式，退出码 0 为成功、2 为失败。

若平台没有 Python 和 Node，**只读取目标行分片**：打开 `references/matrix-rows/R{改善编号}.md`，定位“恶化参数”所在列，按原顺序取原理编号和名称；`null` 表示对角线（转物理矛盾），`空` 表示无优选原理。输出中标注“未执行脚本的确定性资源读取”，复核一次反向单元（读 `R{恶化编号}.md` 中的对应列）以确认行列没有颠倒。不得改用模型记忆，也不必再读取完整 `contradiction-matrix.json`（约 85 KB，人工定位二维数组易错）。

## 5. 用户可见输出模板

| 字段 | 内容 |
|---|---|
| EC1 | IF…THEN 改善…BUT 恶化… |
| EC2 | IF 反向变化…THEN…BUT… |
| 现场改善量 | 名称、单位、测量方法、目标方向 |
| 矩阵改善参数 | `#编号 标准名称` + 映射理由 + 被排除候选 |
| 现场恶化量 | 名称、后果、测量/判废方法 |
| 矩阵恶化参数 | `#编号 标准名称` + 映射理由 |
| 查表方向 | `Rxx × Cyy` |
| 推荐原理 | 按单元原顺序列编号和名称 |
| 现场化构思 | 每条原理至少一个作用机制；拒绝不适用原理时说明理由 |
| 追溯与反证 | 进入哪个方案、解决哪个失效、怎样能推翻 |

## 6. 多映射与收敛

当两个参数都合理时，不要隐藏歧义。查询多个单元，比较：

- 哪些原理反复出现；
- 哪个单元最贴合现场可测量；
- 哪个映射把质量、安全后果表达得最准确；
- 替代映射是否导向不同的可验证机理。

多单元收敛只能增加构思信心，不能增加实证置信度。

## 7. 对角线、空单元和错误路径

- `Rxx × Cxx`：同一参数同时需要相反状态，转为物理矛盾，使用时间、空间、条件或系统层级分离。
- 空数组：经典矩阵没有优选原理。复核映射后，可系统扫描 40 原理、用物—场模型或演化趋势；不得生成一个虚假单元。
- 原理不适用：允许拒绝。记录为什么不适用，不为“用满四条原理”强加危险或复杂结构。
- 查表结果与查新高拥挤机理相撞：回到功能层重构作用拓扑，不把已有专利特征简单拼接为创新。

## 8. 最低质量检查

- EC1/EC2 是否只反转一个控制变量？
- 现场量能否测量？
- 行列是否正确？
- #30/#31 是否混淆？
- 查询是否通过三选一的确定性路径完成（Python `lookup_matrix.py` / Node `lookup_matrix.mjs` / 只读目标行分片 `references/matrix-rows/Rxx.md`，任一即可）？
- 若使用行分片，是否只读取目标行分片并做行列反向复核（用反向单元交叉验证）？
- 原理是否落到作用机制、风险和试验？
- 是否明确“矩阵不证明方案成立”？
