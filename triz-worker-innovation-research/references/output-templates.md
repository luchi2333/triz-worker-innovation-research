# 最小可审计输出模板 v2.4

模板是最低字段，不要求每个案例机械生成同样数量的文档。保持版本号、日期和证据状态。

## 1. 研究台账

统一文件名：`00-研究台账.md`，放在研究工作目录。每轮更新当前阶段、已确认事实、假设、缺口、决策与流程改进。

| 字段 | 内容 |
|---|---|
| 研究目标 | 预期交付和决策用途；交付层级 direction/standard/engineering |
| 原始问题 | 用户原述，不替换口径 |
| 已确认修正 | 修正内容、日期、来源 |
| 当前阶段 | G0…G5、证据模式、允许/禁止动作 |
| 事实 F | 现场已知信息 |
| 实测 M | 方法、样本、结果、原始记录 |
| 来源 S | 命题、来源、日期、边界 |
| 假设 H | 推翻条件和验证编号 |
| 决策日志 | 选择、理由、反对证据；现场否决原文及其影响分析 |
| 流程改进 | 触发证据、旧规则、新规则 |
| 暂停点 | 暂停原因、待用户事项、恢复入口（下一动作 + 所需输入） |

### 1.1 会话检查点（无文件能力时）

平台不能写文件时，在对话中输出同结构的检查点块，格式与台账字段一致：

```text
【检查点】阶段：G_ ｜ 层级：standard ｜ 已确认：… ｜ 待办：… ｜ 恢复入口：…
F：… M：… S：… H：… 下一步：只写一个动作
```

下次会话开始时先请求该检查点块，从其中断处继续，不重做已确认阶段。

## 3.1 TRIZ 完整方向确认稿

首次 TRIZ 输出不能只有上表。按 [triz-analysis-output.md](triz-analysis-output.md) 依次给出：

1. 对象结构与工艺特性（已知/典型情景/未知分开）；
2. 完整工序流及每节点失效；
3. 3～6 个核心工程瓶颈；
4. 系统边界、功能/因果模型、IFR 和资源；
5. 主次技术矛盾的 EC1/EC2、参数映射和逐单元查表；
6. 物理矛盾的相反要求与分离策略；
7. 物—场模型、问题类型、标准解候选和编号依据；
8. 演化/裁剪方向及适用条件；
9. 候选作用机制和系统架构；
10. “瓶颈—TRIZ 工具—参数/模型—原理/标准解—方案—证据—反证”汇总表；
11. 当前不能声称的效果、关键风险和最低成本验证；
12. 用户方向确认问题，并在收到明确回复前暂停深研。

## 7. 两级评价

### 硬门槛

| 路线 | 人身/对象安全 | 不可逆质量 | 合规 | 污染/碎屑 | 可停止回退 | IP 核心碰撞 | 结论 |
|---|---|---|---|---|---|---|---|

### 安全屏障真实性表

| 危险链 | 声称的屏障 | 是否独立于被保护对象 | 最坏公差/磨损/误用/失能 | 单点失效后果 | 检测与验证 | 当前结论 |
|---|---|---|---|---|---|---|

### 加权评分

| 指标 | 定义 | 权重 | 0 分锚点 | 1 分锚点 | 3 分锚点 | 5 分锚点 | 未知规则 |
|---|---|---:|---|---|---|---|---|

| 路线 | 各维度分及证据 ID | 计算式 | 可行性/价值分 | 证据置信度 1～5 | 验证成熟度 V0—V3 | 评分者/日期 | 决策角色 |
|---|---|---|---:|---:|---|---|---|

不要把置信度乘入一个总分掩盖不确定性。未知写 `?` 且分值留空，不得把 `?` 映射为 0、1、3 或其他数值；没有权重、锚点和证据时只作定性比较。每个已给分项另填 `evidence_maturity` 与 `anchor_maturity`；前者低于后者时该分无效，必须降到证据实际支持的锚点或改为未知。

### 8.1 验证一致性检查

| 级别 | 允许结论 | 计划样本/依据 | 已完成样本 | 最不利包络 | 检测及检出限 | 全部通过条件 | 停止条件 | 升级条件 | 是否一致 |
|---|---|---|---|---|---|---|---|---|---|
| V0/V1/V2/V3 |  |  |  |  |  |  |  |  | 是/否 |

升级条件不得低于本级全部样本和判据；按风险增加剖切/显微或等效检测，目视未见不能自动写成“无损”。

V2 是在非生产状态、代表性完整对象或批准的模拟现场完成全流程验证；把试验放入真实生产/检修项目、接入在役系统或影响正式交付时，必须按 V3 受控现场处理并取得相应审批。检测方法必须与失效模式逐项对应，例如绝缘性能与连接/接地连续性不能用同一个数值互相替代。

## 10. 效益模型

至少记录：完整时间、准备分摊、一次合格率、返工、清理、维护、端数、临界批量、是否关键路径。无 M 数据时保留公式和空表，不填假设为“结果”。

## 11. 阶段结论（技术证据附件/内部决策记录）

1. **结论级别：** 概念研究 / 代理评价 / 机理验证 / 样机 / 模拟现场 / 获批现场。
2. **条件性推荐：** 主路线、工程后备、成熟基准、超系统替代。
3. **核心追溯：** 主矛盾参数对、矩阵原理、关键作用机制。
4. **最强证据：** 支持与反对各至少一项。
5. **当前允许：** 下一阶段可执行事项。
6. **当前边界：** 不能声称或实施的事项；不要把本项大段复制进决策摘要。
7. **下一试验：** 最低成本、能改变决策的验证。
8. **退出条件：** 何时停止自研、切换后备或采购。
9. **研究透明度：** 如交付规范需要，在技术证据附件说明 AI 辅助范围和责任复核，不单列为摘要章节。

### 12.4 一页纸成果速览（可选）

只在班组汇报、成果申报或展板等明确需要时生成；不替代决策摘要和主报告，且数字、结论必须与主报告一致，不得单方面拔高。默认 A4 竖版，结构：

| 区块 | 内容 | 上限 |
|---|---|---|
| 标题 | 课题名 + 单位/班组 + 日期 | 1 行 |
| 问题一句话 | 现场话问题 + 主要代价（带口径和 F/M 标记） | 2 行 |
| 推荐方案 | 一张核心机理/动作图（按 Figure Plan 选择）+ “用什么方法解决什么难点”一句话 | 至少约 40% 版 |
| 关键数字 | 效益区间（保守/基准/理想，标注输入状态）+ 验证等级 V0—V3 | 4 行 |
| 安全与边界 | 安全屏障一句话 + “当前不能声称”清单压缩为 2—3 条 | 3 行 |
| 下一步 | 最低成本决定性试验 + 时间点 | 2 行 |

无 M 数据时关键数字只给公式或区间，并写“数据来源：情景假设/现场报告，非实测”；验证等级写实际达到的 V 级，不得写“已验证可用”。
