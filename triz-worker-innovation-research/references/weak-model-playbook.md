# 普通模型可靠执行手册

本手册用于上下文较短、容易跳步、容易凭常识补空或不擅长复杂工程推理的模型。原则是把判断外显成表格和闸门，让模型按确定步骤完成，而不是依赖灵感。

## 1. 永远维护一张进度卡

每次工作开始先读取，结束时更新：

| 字段 | 内容 |
|---|---|
| 当前阶段 | G0/G1/G1.5/G2/G3/G4/G5 |
| 本轮目标 | 只写一个可完成目标 |
| 已确认 F | 用户原述，不推测 |
| 已有 M | 样本、方法、结果；没有就写“无” |
| 已核验 S | 来源 ID + 支持命题 |
| 关键 H | 假设 + 推翻条件 |
| 本轮输入 | 文件、用户答复、搜索结果 |
| 本轮输出 | 文件/章节/表格 |
| 通过条件 | 3～8 个是/否问题 |
| 下一步 | 只写下一阶段的一项动作 |

如果上下文丢失，只凭进度卡恢复，不重建整个研究。

## 2. 四条防幻觉动作

1. **先复制，再解释**：型号、时间、单位、结构、标准号先逐字记录，再分析；
2. **未知留空**：不能确认的材料、尺寸、层序、效果写“未知/待验证”，不用“通常”填成事实；
3. **数字三问**：谁测的？测什么完整口径？能否外推？任一答不上就标 F/H，不能标 M；
4. **来源两问**：来源是否真实？原文是否支持当前命题？只通过第一问不能引用为证据。

再增加三条阻断动作：

5. **标识不纠错**：疑似错字只建候选解释，不覆盖用户原文；没有目标铭牌/文件/实物，不用相似型号冻结结构；
6. **范围不等于适配**：产品标称尺寸、论文对象和专利设想都先与目标逐项比较，不能直接写成可用；
7. **材料不当保险**：被加工对象的一层材料、摩擦、手感、软件或单一传感器不能未经验证承担止挡/保护/联锁。

## 3. G0：问题卡填空法

按顺序填，不允许先生成方案：

1. 谁在什么地点/设备状态下工作？
2. 对什么对象执行哪一套完整工序？
3. 从准备到清理/返工有哪些步骤？
4. 哪一步最耗时/最危险/最易损伤？证据是什么？
5. 必须保留什么功能？不能损伤什么？
6. 现用方法是什么？现行最佳成熟方法是什么？
7. 目标指标是什么，怎样测？
8. 哪些信息缺失？缺失是否阻塞当前研究？

### G0 通过检查

- [ ] 原始问题和后续修正分别记录；
- [ ] 单位和“每件/每批/每项目”等口径未混淆；
- [ ] 完整工序而非单一动作已列出；
- [ ] 硬约束和必须保留功能已列出；
- [ ] F/M/S/H 已分开；
- [ ] 已选择直接或代理证据模式。
- [ ] 原始型号/物料号/标准号逐字冻结；候选别名未覆盖原文。
- [ ] 身份差异若影响结构或安全，已标为阻断项而不是自动规范化。

任一项否：回到问题卡补齐，不进入 TRIZ。

## 4. G1：从瓶颈到 TRIZ 的逐步法

### 4.1 瓶颈句式

每个瓶颈只写一条因果：

`当[变化因素]变化时，因为[直接物理/工艺机理]，出现[可观察失效]，导致[时间/质量/安全/成本后果]；目前未知[信息]。`

如果一句中出现三个“和”，拆成多个瓶颈。

### 4.2 技术矛盾判断树

1. 是否有一个控制变量 `X`？没有：先找根因/作用，不查矩阵。
2. 增大/采用 X 是否改善 A 但恶化 B？不是：不是技术矛盾。
3. 减小/取消 X 是否改善 B 但恶化 A？不是：重写 EC1/EC2。
4. A 和 B 是否是两个不同参数？是：映射矩阵。
5. A 和 B 是否其实是同一参数的相反要求？是：用物理矛盾分离，不查对角线。
6. B 是否为法规、预算、许可或组织问题？是：单列约束，不伪装成工程参数。

### 4.3 参数映射五步

1. 先写现场量、单位、测量方法和期望方向；
2. 从 39 参数中选 2～3 个候选；
3. 对每个候选写“为什么像/为什么不像”；
4. 选择最能表达决策目标且最可测的一个；
5. 运行脚本；复制原顺序输出。

常见分辨：

- 单位时间完整合格产出 → 优先检查 #39 生产率；
- 局部运动快慢 → #9 速度；
- 完整工序被等待/返工拖长 → #25 时间损失；
- 工具伤害目标对象 → #30 作用于物体的有害因素；
- 对象/过程产生碎屑、热、污染伤害外界 → #31 物体产生的有害因素；
- 测量误差大小 → #28 测量精度；
- 制造成品误差 → #29 制造精度；
- 难以检测/测量 → #37，而不是“控制复杂性”；
- 设备部件和连接变多 → #36 装置复杂性。

### 4.4 原理落地六问

对矩阵返回的每条原理逐条回答：

1. 改变哪个对象？
2. 改变什么作用或界面？
3. 使用现场什么资源？
4. 如何改善目标量？
5. 引入什么新失效？
6. 哪个短样试验能推翻？

答不出三项以上时，标“本场景暂不采用”，不要硬凑。

### 4.5 G1 方向稿通过检查

- [ ] 对象结构中 F/M、典型 S、假设 H 分开；
- [ ] 完整工序和 3～6 个瓶颈已写；
- [ ] 系统、功能、因果、IFR、资源齐全；
- [ ] 主矛盾和必要次矛盾都有 EC1/EC2；
- [ ] 每个采用的矩阵单元单独执行脚本；
- [ ] 物理矛盾、物—场和演化没有冒充矩阵结果；
- [ ] 候选机制有风险和反证；
- [ ] 汇总映射表完整；
- [ ] 文末已询问用户并暂停。

## 5. G1.5：用户确认识别

只有用户明确表达“认可/按此执行/这些方向进入深研”并能识别确认范围时才通过。

- 用户补充事实：更新 G0/G1，重新提交受影响部分；
- 用户只选择一条路线：只深研该路线及必要基准/后备；
- 用户只说“继续”但此前尚未看到完整方向稿：不视为确认；
- 用户明确要求跳过某项资料（如照片）：切换代理证据，不把跳过变成已验证。

## 6. G2：深研的五角色串行法

同一模型按以下顺序切换视角，每次只做该角色任务：

### 角色 A 检索者

- 建命题清单；
- 为七条检索轨写中英文关键词；
- 记录检索式、日期、纳入/排除和结果；
- 只收集，不下最终结论。

### 角色 B 核验者

- 核对来源身份；
- 分别给存在性 V/P/L/X、权威 A/B/C/D、直接性、独立性、时效性和目标适配；
- 标记原文支持到哪里；
- 删除虚构、错配和仅搜索片段来源。

### 角色 C 综合者

- 按命题合并支持、反对、边界；
- 输出收敛、分歧、沉默、成熟子功能、拥挤机理和组合空白；
- 回灌修改问题/矛盾/需求/路线。

### 角色 D 反对者

- 找最强反对意见；
- 搜索失败和替代；
- 检查去掉最强来源后结论；
- 把问题分 Critical/Major/Minor。

### 角色 E 编辑者

- 检查每个结论是否有来源/试验；
- 统一术语、编号和边界；
- 将顺序摘要改成跨来源综合；
- 只允许支持强度与证据一致的措辞。

### G2 通过检查

- [ ] 七轨均有结果或不适用说明；
- [ ] 关键命题不使用 L/X 来源；
- [ ] 产品、专利、论文均有 WHY/HOW/WHAT/FIT；
- [ ] 证据矩阵有支持和反对列；
- [ ] 检索回灌修改已记录；
- [ ] 最强反对意见和退出条件已写。
- [ ] 每个声称的检索数量都能逐条对应原始查询式、入口、日期、范围和纳入/排除；
- [ ] 身份、产品适配和跨行业类比均有差异表；
- [ ] “未检得”和专利结论限定到实际数据库/日期/查询式，不写空白、FTO 通过或当然豁免；
- [ ] 若以上任一项否，G2 标“不通过”，下游只能输出证据未闭合草案。

## 7. G3：候选方案机械生成法

不要从零“想五个点子”。按四个槽位生成：

1. `R0 成熟基准`：把成熟子功能组合成当前可实施的最佳流程；
2. `R1 工程后备`：低速、低能量、实体保护、可见、可停止/回退；
3. `R2 探索路线`：来自矩阵/分离/物—场的不同作用拓扑，潜力高但先否证；
4. `R3 超系统`：采购、预制、改变输入、工序前移、取消现场步骤。

每条路线复制以下句式：

`R? 用[工具/介质/场]对[对象]执行[动作链]，通过[作用机制]解决[具体难点]；成熟基础是[来源]，本项目新增集成是[内容]，候选创新差异是[内容]；主要风险[风险]，由[试验]否证。`

若无法写出“作用机制”，该路线只是口号，不能评分。

## 8. G3：先硬门槛后评分

### 硬门槛（是/否）

- [ ] 人员危险能量受限；
- [ ] 目标和非目标对象无不可接受损伤；
- [ ] 必须保留功能有防错/硬边界；
- [ ] 碎屑、污染、卷入和误操作可控；
- [ ] 异常可停止、限力和回退；
- [ ] 无已知法规必然冲突；
- [ ] 核心动作链未被明确有效权利要求完全封死（仅技术初筛）。
- [ ] 每个保护/止挡/联锁均为可识别的独立屏障，且不把对象材料或人工手感当作保险。

任一否：淘汰或重构，不能进入加权排名。

### 评分

对通过路线按同一权重评分。分开给：

- `价值/可行性分`：假设成立时值不值得；
- `证据置信度 1～5`：支持这些假设的证据有多强。

高价值低置信度 = 优先否证，不等于优先制造。

评分前先写指标定义、权重和 `0/1/3/5` 锚点；每个分数绑定证据 ID 和评分者。未知项写 `?`，不得用 3 分或乐观值代填。分数不满足这些条件时，只能做定性比较。

## 9. G4：验证协议填空法

每个关键未知至少一项试验：

| 字段 | 必填 |
|---|---|
| 目标 | 只验证一个机理/失效 |
| 样本身份 | 型号、批次、状态、独立样本 |
| 对照 | R0 或现行最佳方法 |
| 变量 | 一次改变的因素 |
| 记录 | 完整时间、载荷、位移、质量、失败、照片/解剖等 |
| 通过条件 | 可测且预先定义 |
| 立即停止 | 损伤、持续增载、异常位移、污染逸出等 |
| 升级条件 | 何时从短样进入长段/完整流程 |

顺序：代理材料→退役/同批短样→长段连续→完整流程→模拟现场→获批现场。最快一次不代表效率；报告中位数、P90、全部失败和样本数。

升级前做一致性检查：本级计划样本是否全部完成、最不利工况是否覆盖、全部质量/安全判据是否通过、检测方法能否发现隐蔽损伤、停止条件是否未触发。升级条件不得低于本级最低样本与全部判据；“目视未见”不能自动写成“无损”。

## 10. G4：效益不混数

把输入分成三列：

| 输入 | 状态 | 来源/替换计划 |
|---|---|---|
| 现行完整时间 T0 | F 或 M | 现场报告/对照实测 |
| 平台完整时间 T1 | H 或 M | 未试验前必须 H |
| 项目数、端数、人力成本 | F/M/H | 项目记录/财务/情景 |
| 初始成本、运维、耗材 | S/H/M | 报价/BOM/实耗 |

先计算保守、基准、理想情景；只有 M 足够时再改写成实测收益。社会效益给指标，不虚构“避免多少事故”。

## 11. G5：报告装配顺序

1. 先完成主报告各章事实和表格；
2. 再完成每个方案原理图和系统架构图；
3. 再生成技术证据附件和台账；
4. 最后从已完成内容抽取决策摘要；
5. 摘要中逐条检查“方法解决难点”；
6. 做证据/逻辑复核；
7. 做技术表达/视觉版式复核；
8. 实际打开或渲染最终文件逐页检查。

不得先写摘要再倒推证据；不得把附件中的行政/声称控制大段复制进摘要。

## 12. 两轮最终复核

### 第一轮：证据与逻辑

随机抽查至少：

- 3 个现场事实；
- 3 个矩阵单元；
- 5 个关键外部命题；
- 每个入选方案 1 个成熟来源和 1 个创新差异；
- 3 个效益输入；
- 最强反对意见。

每项必须能回到 F/M/S/H、脚本或来源 ID。

再对每一句“推荐、适配、安全、空白、专利、效果”结论执行七问：

1. 是否改写了原始标识/口径？
2. 原文是否直接支持，不只是页面存在？
3. 来源和目标的关键边界是否相同？
4. 是否把类比机理写成目标可行？
5. 是否把未经验证的材料/感觉/软件当成安全屏障？
6. 是否越界写成市场不存在、首创、FTO 或侵权豁免？
7. 当前验证等级是否足以支持该成熟度？

任一回答不利或未知：降为 H，补限定、推翻条件和下一验证，重新判定阶段；不得只换一个委婉形容词后保留同一结论。

### 第二轮：技术表达与版式

- [ ] 摘要首先呈现技术方案；
- [ ] 路线表不是只有名称，明确方法和难点；
- [ ] 推荐方案有连续动作链；
- [ ] 原理图与文字一致，且标概念/非制造图；
- [ ] 表格无截断、重复表头正确、跨页可读；
- [ ] 标题、图号、路线号、模块号一致；
- [ ] 没有损坏占位符、乱码或无来源精确数字；
- [ ] DOCX/PDF/Markdown 实际查看通过。

## 13. 卡住时的恢复表

| 卡点 | 不要做 | 正确恢复 |
|---|---|---|
| 不知道真实结构 | 猜典型结构为事实 | 建 3 个代理情景和最不利包络 |
| 不会选矩阵参数 | 按关键词随便选 | 写现场量→候选→理由→脚本查多个单元 |
| 矩阵为空 | 从别处凑 4 个原理 | 复核映射，转物理矛盾/物—场/40 原理扫描 |
| 搜不到同类产品 | 写“市场没有” | 按功能/失效/动作/物理效应扩检并限定范围 |
| 方案太抽象 | 加更多形容词 | 补对象、动作、力/场、界面、输入输出和失效 |
| 证据互相冲突 | 任选支持推荐的 | 比对象/方法/场景；写条件关系或保留未解冲突 |
| 报告太长但方案不清 | 删技术细节 | 先压缩治理性内容，保留方法—难点—作用链 |
| 无法生成 Word/PDF | 宣告无法交付 | 交付完整 Markdown/CSV/PNG，保留同一结构 |
