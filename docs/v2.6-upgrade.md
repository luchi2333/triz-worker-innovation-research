# v2.6：从现场输入到同源图文报告

本次升级把现场输入、需求、机制、参数、试验和最终表达连接起来。保留经典矩阵、阶段门和领域图型；核心脚本仅依赖 Python 标准库，PNG 渲染可选用本机 Chromium 浏览器。

## 使用顺序

1. 从 `assets/research-record-template.json` 建立课题记录。逐字保存原话与位置，把现场报告 F、受控实测 M、外部来源 S、工程假设 H 分开。G0 未知量保留未知；空白记录不预置具体方案。
2. 按问题选择补充观察、常规改进或 TRIZ 方法。用 `validate_research.py --complete-stage G0` 检查问题定义；已有明确方向委托记录后沿用，不重复请求同一授权。
3. 用机制卡说明输入经过哪个部件/界面，改变哪个量，需要什么条件，怎样否证。查询必须逐次记录真实日期、范围和排除理由。无联网记录不能宣布 G2 完成。
4. 以试验协议、实际结果与原始文件散列支持 M 命题和 V1—V3。硬门槛失败、主动作用冲突、接口缺口会阻止路线保留为主推荐。失败试验仍是证据，不支持通过判据的成熟度。
5. 从记录中的参数和图形定义生成 SVG、可选 PNG 和 HTML 分步图解。图按实际机制绘制；动态图组说明每个状态，初步设计图标识关键尺寸和未知项。
6. 报告源通过稳定 ID 引用参数、命题、表格与工程图。生成 Word 后校验实际正文和嵌入图片，另做逐页视觉复核。修改记录后，旧图和旧报告须重新生成。

完整接口：[研究记录与图文契约](../triz-worker-innovation-research/references/research-record-contract.md)；可执行结构：[教学记录](../triz-worker-innovation-research/assets/tutorial-record.json)。教程全为 H，不是现场研究成果。

在 skill 根目录执行：

```bash
python scripts/run_tutorial.py --output tutorial-output
python scripts/run_tutorial.py --output tutorial-png --png-browser "path/to/chromium"
python scripts/validate_research.py --record research-record.json --previous previous-record.json
python scripts/build_report.py --input report-source.json --output report.docx --verify-bindings
python scripts/validate_skill.py --strict
```

`--verify-bindings` 检查已有 DOCX；省略时生成并自检。Windows 建议设置 `PYTHONUTF8=1`。教程输出目录必须为空或尚不存在，避免覆盖旧候选。

## 兼容与检查边界

| 文件 | 当前 schema | 旧文件处理 |
|---|---|---|
| 研究记录 | 1.1 | 1.0 可读；`--migrate new.json` 复制迁移，原始字段保留，新增证据/授权不自动编造 |
| 报告源 | 1.3 | 1.2 可读，正文绑定为 `LEGACY_UNCHECKED` |
| 交付清单 | 1.2 | 沿用既有结构；DOCX artifact 增加 `report_source_path`，引用当前研究记录 schema |

报告源按工程图首次出现顺序生成图 1、图 2……；交付清单 `figures[].number` 与 `report_figure_order.ordered_numbers` 使用相同序列。旧章内图号仍可读取；同一报告不混用两种编号。图组清单是生成文件的散列索引，不能代替交付清单的用途、标签、领域覆盖与实际复核结果。

结构通过、计算一致性、研究进度、路线资格、技术成熟度和现场动作授权分别报告。`check_scope` 给出实际检查数量：模型为零时没有做效益计算。G0 尚无候选方案时，V0 兼容默认值不表示机理已获评定。

正文绑定只覆盖声明绑定的块；自由叙述仍需内容审查。原始文件存在和散列一致不证明测量真实。SVG 几何正确不证明力学成立。初设为带参数的二维表达；本版没有自动生成 CAD/STEP、制造公差或完成真实试验。

## 可重现回归

新增 `scripts/test_pipeline.py` 随 strict 检查运行，覆盖现场引用、阶段完成、门槛、相互作用、原始数据、负面试验、基准证据、单位、评分、正文金额偏离、有效尺寸检索、Word 内容篡改、段内拆分、换图、参数变更、旧图拒绝、图序、SVG 交付要求与旧数据迁移。保留原有 15 项交付自检、18 组 Python/Node 行为一致性、16 个黄金矩阵单元和 39 个行分片检查。CI 中的 strict 入口会执行新增测试。

实际浏览器交互与 Word 排版需要另外检查，不能以单元测试替代。没有真实来源和试验的教学输出不运行成“完整工程交付通过”。
