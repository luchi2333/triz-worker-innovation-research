# TRIZ 职工创新 Skill 优化实施计划

日期为 2026-11-06。状态为待实施。

本计划依据 [优化方案](triz-research-report-quality-optimization-2026-11-06.md)，结合本地代码制定。实施基线为 `19e20f4a2b4d2d9e0b46a214fd609146be0a7d7c`，Skill 标称版本为 2.9.0。该提交包含发布标签之后的改动，比较时使用完整提交号。

目标是提高创新方案的工程价值，以及报告的证据可信度、可复算性和读者理解程度。首轮采用 12 题试点，最多处理两类高频失误。规模、排期和试点判据为本计划的建议值，执行前写入冻结的评估协议。

## 3. M0 — 建立能发现问题的评估资产

### 3.1 题库与隔离

首批全部使用公开或虚构的离线研究场景，每类 4 题。

| 类别 | 覆盖重点 | 开发集 / 留出集 |
| --- | --- | --- |
| 机械工装 | 夹持变形、电缆开剥、限位导向、维护替换 | 3 / 1 |
| 电气与测量 | 测量端口、精度与速度、干扰与滤波、不可辨识或信息不足 | 2 / 2 |
| 工艺与作业 | 效率与差错、资源与等待、返工控制、可直接改进而无真实矛盾 | 3 / 1 |

每题保存用户原始输入、边界、可用资料、允许追问及预设回答、硬约束。评审专用标签另存，包含可接受的多组参数映射、合理拒答条件、关键错误和评分依据。标签不进入被测模型输入。

单双屏蔽电缆开剥安排在开发集，因为优化方案已详细描述该场景。现有薄壁铜管教程仅用于通路检查。留出题由独立评审者管理，调优者在候选提交冻结前只看到类别和数量。若无法做到隔离，结果标为开发集复核，并补充未参与调优的新题后再作推广判断。

### 3.2 比较条件

| 组别 | 输入方式 |
| --- | --- |
| A | 相同任务目标与交付要求，使用模型默认能力 |
| B | 相同任务加固定的普通 TRIZ 提示 |
| C0 | 使用基线提交中的完整 Skill 指令 |
| C1 | 使用冻结候选提交中的 Skill 与待评改进 |

各组独立会话，使用同一模型版本、相同工具权限、资料包、预算和输出要求。隔离 Skill 自动加载，记录实际加载内容，防止 A/B 意外获得 C 组指令。G1.5 所需答复使用题库中事先冻结的用户回答，在实际提出确认后提供。无回答的交互失败单独记录。

先用独立的 3 道通路题估计成本，再冻结每题的时间、检索和输出预算。预算耗尽保留原始失败和费用，重试另编号并保留原因。宿主取不到的 token、模型参数等填 `unavailable`。

第一层评估统一覆盖问题建模、研究证据、候选机制、验证设计和决策摘要，并评阅各组按各自流程实际完成的交付物。第二层在 M4 单独检查三类完整 DOCX，验证排版、图文和最终文件链路。

### 3.3 评分与记录

六项 0–4 分为事实与约束、矛盾映射、机制与差异、创新归属、可行性与否证、报告证据与可读性。每个分值有锚点，每次评分引用输出原句。评审先独立提交评分，再讨论分歧，保留讨论前后记录。

匿名程序隐藏组别、模型和提交信息，为每名评审随机排列输出，保存可追溯映射。技术内容完整保留，评审记录其是否猜到组别。

伪造实测或来源、把计划写成完成、无依据提升成熟度、越过确认及无依据现场安全声称均单列关键错误。主表同时展示六项分数和关键错误，分别报告全部输出及合格输出的结果。

建议新增目录如下，全部位于仓库根的 `evals/worker-bench/`。

- `README.md`、`protocol.md`、`rubric.md`，定义运行、冻结、评分与争议处理。
- `cases/` 保存模型可见题目，`annotations/` 保存评审标签，运行器只读取前者。
- `splits.json` 保存划分与哈希，留出资产按隔离要求延后公开。
- `prompts/` 固定 A/B/C 指令包装与输出要求。
- `prepare_review.py` 生成匿名评审包，`summarize_results.py` 汇总配对结果。
- `results/<run-id>/` 保存输入引用、原始输出、运行清单、评分及结果报告。

首轮采用宿主执行加文件收集。运行清单同时承接原方案 P1-3，记录提交、模型可用元数据、输入哈希、工具、检索、耗时、成本和人工修正，避免重复建设调度系统。

## 4. M1/M2 — 根据基线选择最多两项改进

完成开发集 24 份输出后，按关键错误优先、出现频次其次、修复收益再次排序。一般问题至少在两道题复现才进入首批；严重错误可凭单例最小复现进入。以下两项是优先候选，实际顺序由基线决定。

### 候选一 — 候选映射卡

先从现有控制变量方向卡提取信息，在评估附表记录候选参数、原始证据句、因果依据、置信说明和复核需求。先确认现有表达遗漏了什么，再补指令。

开发阶段将候选提示和 `mapping-review.json` 放在评估目录，通过 C1 试验包装加载。独立测量方向颠倒率、Top-1/Top-3 可接受映射、参数对 precision/recall/F1，以及合理拒答和错误强制映射。对无真实矛盾题单独评分，指标分母明确列出。

至少覆盖因果成立、方向颠倒、多组合理参数、因果待证、无技术矛盾五类样例。预期输出与人工标签由评审维护。

### 候选二 — 关键主张支持度审计

生成 `claim-evidence-review.json`，引用现有 claim/source/test ID，绑定报告版本或文件哈希，保存原句、定位、声称强度、证据类别、支持状态、适用边界和处理结果。

优先覆盖摘要全部关键主张，以及创新性、效果、安全、适配和成熟度结论。来源标识有效与来源支持结论分别记录。自动检查处理 ID、定位、状态和记录完整性；支持关系由阅读来源后的复核者判断。

冻结以下负例及对应正例，防止简单删除全部数字或拒绝全部主张获得高分。

| 负例 | 期望处理 |
| --- | --- |
| 来源仅验证部件，报告宣称整机 V3 | 限定到部件及来源工况，整机待验证 |
| 无 M 数据，声称效率已提升 30% | 改为有假设依据的预测或删除数字 |
| 以专利摘要证明本方案首创 | 改为相似先例与差异说明，保留查新边界 |
| 同一试样重复测量被当作独立样本 | 修正样本单位及区间方法，重审结果 |
| 试验协议被写成已完成试验 | 恢复计划状态，撤回相应实测结论 |

正例包括来源范围吻合的部件结论、明确标 H 的算例、带匹配原始数据的实测主张。开发集候选验证通过后，冻结 C1 的代码、提示和评估协议。

## 5. M3 — 留出评价与去留决定

冻结后才运行 4 道留出题的 A/B/C0/C1，共 16 份结果。开发集 C1 首轮增加 8 份，因此计划核心运行量为 48 份，另有通路题、必要复现和后续 DOCX 验证。最终成本在通路测量后登记。

首轮建议预注册以下推进判据。它们用于决定是否继续投入，4 道留出题只能形成探索性证据。

1. C1 在留出题上新增关键错误为 0，方向颠倒数相对 C0 不增加。已有关键错误逐个修复并复核，带错误成果不能作为合格示例。
2. 两项拟改进各自至少在 2 道适用留出题上可评价。若不满足，结论为证据不足，并在查看新题前重新冻结候选版本。
3. 对适用留出题，目标维度的双评委平均配对增益至少 0.5 分，其他维度平均下降不超过 0.25 分。逐题下降仍须解释。
4. 摘要关键主张逐条复核完成，不支持或无法核验的强结论均已修订；正例能够正常保留。
5. 首轮建议将可比较的运行成本中位数增幅和人工审查分钟数增幅分别控制在 25% 内。超出时先压缩重复步骤并复测；成本信息不完整时注明判据未核实。

同时比较 C0、C1 与 A/B，列出哪类题受益、哪类题退步。若 C1 改善 C0 但仍逊于简单基线，先查原因再扩展。分项评价一致性使用适合序数量表的加权 Kappa，极小样本同时展示原始评分和分歧数；不把单个一致性系数当作充分证据。

若只有一项改进获得支持，集成该项。两项合用结果含混时，在开发集补做逐项对照。留出题结果用于修改后，该批题转为已使用题，下次推广评价另取新题。

## 6. M4 — 集成到主流程与报告出口

### 6.1 经验证的规则集成

只把收益成立的规则纳入正常入口。包内新增文件同步维护 `validate_skill.py` 清单。升级为 MUST 时，逐项落实五层契约。

| 层次 | 预计改动位置 |
| --- | --- |
| 规范 | `SKILL.md` 及相关 G1/G2/G4/G5 参考文档 |
| 事实源 | `assets/research-record-template.json`、`references/research-record-contract.md` |
| 报告出口 | `scripts/report_bindings.py`、报告源模板及必要的 `build_report.py` 路径 |
| 自动校验 | `scripts/research_contract.py`、`validate_research.py`、`report_quality.py` 中实际负责的入口 |
| 负向回归 | `scripts/test_pipeline.py`、`test_report_quality.py`，同步 `requirement-coverage.json` |

修改 schema 前盘点已支持版本及其现有行为。旧记录能够按既有兼容方式读取，新增审查缺失时给出准确的未检查状态。迁移保留已有证据和 ID，新增人工结论留待填写。覆盖旧记录、完整新记录、缺字段新记录、更新后报告绑定及重复迁移。只在正式接入需要时增加迁移脚本。

### 6.2 试验统计与读者入口

在 `deep-research-protocol.md` 和 `technical-report-quality.md` 中接入已验证的主张支持审查。新增 `experimental-design-and-statistics.md` 时，由 G4 按重复测量或效果对比需求加载，说明样本单位、基准、顺序平衡、测量误差、异常处理和效果不确定性。缺样本时交付验证协议。

在 `final-report-blueprint.md` 与 `output-templates.md` 中扩展评奖答辩、工程审查两种阅读入口，复用研究记录与当前渲染器。先改内容组织，发现渲染能力不足再改脚本。

各选机械、电气/测量、工艺一题，对 C0/C1 生成完整成果，共 6 套。两名复核者只阅读最终报告，分别复述问题、机制、差异、证据成熟度，并追算一个示例、定位一个失效反例、说明最低验证步骤。检查图文一致、分页、表格和正文关键证据，保存具体问题与修订记录。

## 8. 停止与恢复条件

- 评委对评分锚点持续存在明显分歧，先在开发题校准并重新冻结规程。
- 出现来源伪造、H/M 混淆或错误成熟度提升，先修复最小复现，再继续推广评价。
- 新规则误拦截正确正例，保留评估期可选状态并修正适用条件。
- 质量增益未达到预注册判据或成本超预算，停止主链扩展，保留原始结果用于判断后续价值。
- 主链改动破坏已有合同，按独立提交回退该改动，原始研究记录和评估材料保留。

条件式 TRIZ 深化、扩大到 30–100 题、常驻多代理和检索适配器留待首轮结果决定。下一项可执行工作是 M0 的评估协议、12 题目录与评分锚点草案，随后完成独立标注和运行预算冻结。
