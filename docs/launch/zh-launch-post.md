# 中文首发文案

## 标题

我把一套“先研究、再提方案”的 AI + TRIZ 工程创新流程做成了开源 Agent Skill

## 正文

把真实工程问题交给 AI 时，我遇到的最大问题不是“它没有点子”，而是它太快给出点子：问题边界没有还原，矛盾矩阵可能凭记忆，搜到的产品和专利没有核验适配性，最后也没有说明怎样否证。

所以我把一套用于职工创新研究的流程整理成了开源 Skill：

```text
现场事实 → 工序与系统边界 → TRIZ 矛盾 → 39×39 矩阵
        → 用户确认 → 产品/专利/标准/论文查新
        → 候选方案 → 风险与 FMEA → 验证试验 → 技术报告
```

它内置经典 39×39 矛盾矩阵，支持 Python、Node 和无脚本行分片三种确定性查询；每个结论区分现场报告、受控实测、外部来源和工程假设。第一次完整 TRIZ 分析后必须暂停，由用户决定哪些方向值得继续深研。

这个项目不承诺“自动发明”，也不把有限专利检索写成 FTO，更不会在没有实测时声称提效。它想做的是把 AI 工程创新从一次脑暴，变成一条可追溯、可质疑、可验证的研究链。
